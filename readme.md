# Серверная часть информационной системы MiaBox

![Схема](https://github.com/gnom48/miabox_api/blob/v3/assets/MiaBox%20Server.png)

## Summary
Репозиторий содержит серверную кодовую базу проекта MiaBox. Представляет собой набор микросервисов, обеспечивающих основную логику работы системы.

## Технологический стек
*   **Языки и фреймворки:**:
    - Python (FastApi, SqlAlchemy, Pydantic, ...)
    - Go (gorilla/mux, pq, swaggo, ...)
*   **Инфраструктура:** RabbitMq, Redis, Nginx, Postgres
*   **Базы данных:** Единая БД PostgreSql
*   **Еще:** Интеграция с моделями Whisper (для транскрибации аудио)

## Структура проекта и компоненты
Проект организован по принципу микросервисной архитектуры. Основные компоненты (директории в корне):
*   **`auth/`** — Сервис аутентификации и авторизации.
*   **`core/`** — Основной бэкенд, ядро бизнес-логики.
*   **`knowledgebase/`** и **`knowledgebase2/`** — Сервисы базы знаний (возможно, разные версии).
*   **`whisper/`** — Микросервис для работы с аудио, использующий модель Whisper.
*   **`nginx/`** — Конфигурация reverse proxy для сокрытия внутренней структуры бэкенда.
*   **`docker/`** — Dockerfile и вспомогательные файлы для сборки образов.
*   **`assets/`** — Статические ресурсы.

## Инфраструктура и запуск
*   **Контейнеризация:** Весь проект запускается в Docker-контейнерах. Для оркестрации, используется `docker-compose`.
*   **Reverse Proxy:** Nginx выступает в роли единой точки входа извне, распределяя трафик между внутренними сервисами самостоятельно.
*   **CI/CD:** В проекте была попвтка настроить автоматическая сборка и деплой с помощью **GitLab CI** (конфигурация в `.gitlab-ci.yml`), но потом я на нее забил))

### Как запустить
1.  Убедитесь, что установлены Docker и `docker-compose`.
2.  Клонируйте репозиторий.
3.  Запустите сборку и запуск контейнеров:
    ```sh
    docker-compose up --build
    ```
